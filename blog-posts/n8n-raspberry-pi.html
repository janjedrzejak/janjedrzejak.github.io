Self-Host n8n on Raspberry Pi 3+ Complete Setup Guide

25 NOV 202522 MINJAN JĘDRZEJAK

You can use a Raspberry Pi as a small n8n learning environment with Docker and persistent storage. The Pi 3 Model B+ has 1 GB of RAM, so treat it as a constrained test machine and measure your own workload. This guide uses local access through an SSH tunnel; it does not publish the editor to the internet.

What do you need before installing n8n?

Use a 64-bit operating system supported by your Docker installation, SSH access, a reliable power supply and storage with enough free space for images and execution data. Confirm that the selected n8n image tag includes an ARM64 build. A 64-bit processor alone does not mean that the installed operating system is 64-bit.

Raspberry Pi documents 1 GB of RAM for the 3 Model B+. There is no defensible fixed number of simultaneous workflows for every installation: large JSON responses, attachments, code execution and parallel runs have very different memory needs. For this guide, start with a single small workflow.

Raspberry Pi 3 Model B+: specification / specyfikacja

1. Check the system and install Docker

On the Pi, check the architecture, memory and disk space. For the ARM64 setup described here, uname should report aarch64. Then use the official Docker instructions for your operating system and verify that Docker Engine and the Compose plugin work.

uname -m
free -h
df -h
docker --version
docker compose version
sudo docker run --rm hello-world

Docker Engine installation for Debian

Commands below use sudo for Docker access. Membership of the docker group grants powerful access to the host; it is a permissions decision, not a requirement for this tutorial.

2. Create a versioned Docker Compose configuration

Create a directory for the configuration and save the example below as compose.yaml. Create an .env file beside it containing N8N_VERSION= followed by the exact release tag you selected. Use the n8n releases page to check the release and breaking changes, and verify that the image supports linux/arm64 before starting it.

n8n releases

services:
  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION:?Set an exact n8n release tag in .env}
    restart: unless-stopped
    ports:
      - "127.0.0.1:5678:5678"
    volumes:
      - n8n_data:/home/node/.n8n

volumes:
  n8n_data:

The named volume keeps n8n data when the container is recreated. The host binding limits the published port to localhost with current Docker versions. This is a minimal learning configuration, not a tested capacity claim for Pi 3 hardware. Do not replace the loopback binding with a public interface without designing authentication, HTTPS and network access.

Docker: published ports and localhost binding

3. Start the container and open an SSH tunnel

Run these commands from the directory containing compose.yaml on the Pi. Review logs for startup failures instead of assuming that a running container means the editor is ready.

sudo docker compose config
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 n8n

From your own computer, open the tunnel below, replacing USERNAME and PI_ADDRESS with your SSH user and Pi address. Keep the tunnel open, then visit http://localhost:5678 in your browser and complete the n8n account setup. The editor travels through SSH; external services cannot reach local webhook URLs through this setup.

ssh -N -L 5678:127.0.0.1:5678 USERNAME@PI_ADDRESS

4. Verify persistence and measure resource use

Create a small manual workflow, save it, restart the container and confirm that the workflow is still present. Run a few representative executions and inspect container memory use. Do not use docker compose down -v for a routine restart: the -v flag removes named volumes.

sudo docker compose restart n8n
sudo docker stats --no-stream

5. Plan backups and updates

A persistent volume is not a backup. Keep a separate, access-controlled copy of the data and the encryption material required to recover credentials. For a simple stopped-instance backup, stop n8n before copying its volume, then start it again. Test restoration in an isolated environment before you depend on the backup.

Before updating, read release notes, create a restorable backup and test the new release. Change the explicit image tag only after that review. Database migrations may make an old container incompatible with upgraded data; rollback can require restoring the matching backup rather than just selecting the old image.

Common questions about n8n on Raspberry Pi

Can a Pi 3 B+ run every n8n workflow?

No. Its 1 GB RAM is a significant constraint. Test the current release with a small workflow and inspect actual memory use. Large files, intensive code or parallel processing can require a machine with more resources.

Does self-hosting keep all data on the Pi?

It keeps the local application data where you host it. Connected APIs, cloud AI models and other configured services may receive workflow data. Review each integration and deployment setting before processing confidential information.

Is n8n an unrestricted open-source product?

n8n describes itself as fair-code and source-available. Its repository identifies the Sustainable Use License and an Enterprise License. Check the applicable license for your use case.
